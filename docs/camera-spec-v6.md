# Snappi カメラ振る舞い仕様 v6（編集者の考え方に基づく自動編集）

**Status**: 実装済み（#39）
**Issue**: #39（採点 #38、前版 #28 / #29）
**Previous**: `old/camera-spec-v5.md`（注目点 = カーソル。区間は R1〜R5、追従は F1〜F5）
**Last Updated**: 2026-10-13

---

## 1. 目的

録画して停止したら、**ユーザーが編集しなくてもそのまま使える動画**ができること。

v5 はメトリクス上は合格していたが、編集者の目で見ると（#38）「どこを映すか」が外れていた。原因は「注目点 = マウスカーソル（またはクリック位置）」という前提で、実際の操作で見るべき場所はマウスではなく**画面の中で変化が起きている場所**であることが多い。

v6 では「人がパン・ズームを使って編集するならどうするか」を原則（§2）として言葉にし、それを特定のアプリに依存しない汎用的なアルゴリズム（§4〜§6）にする。**アプリ向けの分岐は持たない。**

パラメータの実体は `src-tauri/src/camera/spec.rs`、実装は `src-tauri/src/camera/`（主役 `subject.rs`、ショット `segments.rs`、カメラトラック `track.rs`）と `src-tauri/src/changes.rs`（変化領域）、メトリクスは `src-tauri/src/eval/metrics.rs`。値を変えるときは本書とコードの両方を更新すること。

## 2. 編集者ならどう編集するか（原則）

| # | 原則 | 対応する規則 |
|---|---|---|
| P1 | **見るべきもの（主役）を映す**: 文字を打っているなら入力行と変換候補、メニューなら開いたメニュー、ダイアログならダイアログ全体、スクロールならスクロールしている内容 | S1 |
| P2 | **主役が収まる大きさで寄る**: 倍率は固定ではなく、主役が余白付きで収まる大きさ。読めないほど小さければ寄り、収まらなければ引く | S3 |
| P3 | **場面単位で考える**: 同じ場所・同じ目的の一連の操作（メニュー → ダイアログ → 入力）は 1 つの場面として、カメラを落ち着かせる | S4 |
| P4 | **意味のない動きには寄らない**: 何も変化しないクリック、画面の端から端への移動、操作していない時間は全体表示 | S2, S3 |
| P5 | **操作中のウィンドウの外は映さない** | S5 |
| P6 | **動きは少なく、先回りする**: ショットの間はカメラを止め、ショットが変わるときだけ動く。録画後に処理するので、操作の前から動き始める | F6, R3 |

## 3. 信号

どのアプリでも取れる信号だけを使う。

| 信号 | ファイル | 使い方 |
|---|---|---|
| **画面の変化領域** | `changes.jsonl`（`changes.rs`） | 主役の位置と大きさの主な手がかり |
| 操作 | `events.jsonl` のクリック・ドラッグ・キー入力・スクロール（R1, R5） | 「いま操作している」時刻と、どの変化が操作の結果か |
| 前面ウィンドウの矩形 | `window_events.jsonl` | 枠を収める範囲（S5） |
| マウス | `events.jsonl` の移動 | **主役には使わない**（クリック・ドラッグ・スクロールの位置だけを使う） |

### 3.1 変化領域（`changes.jsonl`）

隣り合う録画フレームの差分から、まとまって変化した領域を矩形にする。録画の停止時に作る（旧録画はプレビューを開いたとき・書き出し時に作る）。frames は大きく評価データにコミットしないため、評価もこのファイルだけを使う。

- フレームを 16px のセルに分け、セル内の画素（2px 間引き）で輝度の差が 24 を超える画素が 2 つ以上あればセルが変化したとみなす（JPEG のノイズを除く）
- 変化したセルを、距離 2 セル以内でつなげた連結成分の外接矩形を 1 つの領域にする
- 1 行 = 1 フレーム `{"t":1124,"rects":[[l,t,r,b,cells],...]}`（キャプチャ領域基準の px、変化したセル数）。変化の無いフレームは書かない
- ノイズの除去や操作との対応付けはしない（生の信号）。`snappi-eval <dir> --changes` で作り直せる

## 4. 主役（`camera/subject.rs`）

| ID | 規則 | パラメータ |
|---|---|---|
| S1 | 操作ごとに「その操作の結果として変化した領域」を主役にする。反応の時間帯は操作から `RESPONSE_MS` 以内で、位置のある次の操作（クリック・ドラッグ）で打ち切る（続けて打つキー入力・続けて回すスクロールでは打ち切らない）。<br>候補から次を除く: セル数が `MIN_CHANGE_CELLS` 未満、常に動いている場所（操作の無い時間 = 前後 `AMBIENT_IDLE_MS` に操作が無いときに変化した `AMBIENT_MAX_CELLS` 以下の領域。キャレットの点滅・時計など）、反応の中で最大の変化の `FRAGMENT_RATIO` 未満の小さな片（操作位置を含むものは残す）。<br>種（起点）は、位置のある操作ならその位置、キー入力なら直前の入力の主役に近い変化（無ければ最大の変化）。種から `NEAR_PX` 以内の候補と、`BIG_CHANGE_CELLS` 以上の候補（離れて開いたダイアログ等）を取り込んで広げる | `RESPONSE_MS` = **1.2s**, `MIN_CHANGE_CELLS` = **3**, `AMBIENT_IDLE_MS` = **1.5s**, `AMBIENT_MAX_CELLS` = **30**, `FRAGMENT_RATIO` = **3%**, `NEAR_PX` = **160px**, `BIG_CHANGE_CELLS` = **300** |
| S1' | スクロールの主役が寄った枠（倍率 Z）より大きければ、操作位置の周りの枠に入る分だけにする（長いページ・ペインのスクロール） | |
| S2 | 画面が変化しないクリックは**意味のない操作**（主役は位置だけ。寄る理由にならない）。反応の無いキー入力（修飾キーだけ等）は主役を持たない。クリック・キー入力・ドラッグの反応が寄れないほど大きい（`fit_zoom < MIN_SHOT_ZOOM`）なら**画面の切り替え**（場面転換、寄らない） | |

## 5. ショット（`camera/segments.rs`）

主役を時間順にまとめて「ショット」（枠を固定して映す時間帯）を作る。ショット = `ZoomSegment { zoom: Some(倍率), focus: Fixed { 枠の中心 } }`。全体表示のショットは区間にしない。

| ID | 規則 | パラメータ |
|---|---|---|
| S3 | 倍率は、ショットの主役の和を余白 `SUBJECT_MARGIN` 付きで収める最大の倍率（上限はズーム強さ Z）。`MIN_SHOT_ZOOM` 未満なら全体表示。意味のある操作（S2）を含まないショット・画面の切り替えのショットも全体表示 | `SUBJECT_MARGIN` = 幅・高さの **2.5%**, `MIN_SHOT_ZOOM` = **1.25** |
| S4 | 次の主役を今のショットにまとめる条件:<br>・間隔が `MERGE_GAP` 未満で、まとめても倍率が「このショットで一番寄れていた倍率」の `SHOT_ZOOM_KEEP` 倍以上（倍率が大きく下がるなら次のショットへ。少しずつ下がり続けないよう最良値と比べる）<br>・間隔が `SCENE_BRIDGE` 未満で、今の倍率をほぼ保ったまま（95%）収まる（間が空いても同じ場所の操作なら場面を続ける）<br>・スクロールで、主役の `SHOT_COVER_RATIO` 以上が今の枠に入っている（枠を広げずに続ける）<br>まとめない場合でも、間隔が `SCENE_BRIDGE` 未満で主役同士が `NEAR_PX` 以内なら、寄ったまま次のショットへ移る（間で全体に戻らない） | `MERGE_GAP` = **3.0s**, `SHOT_ZOOM_KEEP` = **0.85**, `SCENE_BRIDGE` = **8.0s**, `SHOT_COVER_RATIO` = **70%** |
| S5 | 枠は主役の中心を基本に、操作開始時の前面ウィンドウの矩形（主役を `WINDOW_TOLERANCE_PX` の誤差で含む場合）の中、さらにフレームの中に収める。主役は枠から外さない。枠がウィンドウより大きくなる場合は、主役が収まる範囲で倍率を上げてウィンドウの中に収める | `WINDOW_TOLERANCE_PX` = **24px** |
| R3 | ショットは最初の操作の `LEAD` 前に始め、最後の操作から `HOLD` 後（反応が最後に見えた時刻から `RESPONSE_HOLD` 後の遅い方）まで続ける | `LEAD` = **0.6s**, `HOLD` = **1.5s**, `RESPONSE_HOLD` = **0.8s** |
| R4 | 寄ったショット同士の隙間が `MIN_GAP` 未満ならつなぐ。寄ったショットの後が全体表示なら、その操作までに引き終える。全体表示の後に寄るときは、全体表示を保つ必要がある時刻（画面の切り替え・クリックの位置を見せる）の後に寄り始める。孤立した寄ったショットは `MIN_SEGMENT` 以上に延ばし、延ばせなければ寄らない | `MIN_GAP` = **1.5s**, `MIN_SEGMENT` = **2.0s** |
| R5 | 録画冒頭と末尾の Snappi 自身の操作は対象外（v5 と同じ） | `START_GUARD` = **1.0s**, `END_GUARD` = **1.5s** |
| R1 | クリック・文字入力・スクロール・ドラッグを「操作」とする（v5 と同じ） | `DRAG_MIN_DISTANCE` = **10px** |

## 6. カメラの動き（`camera/track.rs`）

| ID | 規則 | パラメータ |
|---|---|---|
| F6 | ショット（`Fixed` の区間）の間はカメラを止める。ショットへ移るときは、移った先の枠の中心を anchor にして、今の画面上の位置から画面の中央へ動かしながら倍率を変える（寄る・引く・パンを 1 つの動きにする）。時間は寄るとき `ZOOM_IN`・引くとき `ZOOM_OUT` を基本に、遠い移動ほど長くして速度上限を超えないようにする（最大 `SHOT_MOVE_MAX`） | `ZOOM_IN` = **0.5s**, `ZOOM_OUT` = **0.7s**, `MAX_PAN_SPEED` = **2.5 画面幅/秒**, `SHOT_MOVE_MAX` = **1.2s**、補間は ease-in-out（cubic） |
| F3 | ビューポートは常にフレーム内に収める（v5 と同じ） | |

`focus: Auto` の区間（v5 の project.json）は v5 の F1〜F5 のまま動く（互換）。

## 7. 録画と自動トリム

| ID | 規則 | パラメータ |
|---|---|---|
| C1 | 録画は設定のフレームレート（少なくとも 30fps）で記録する。キャプチャのスレッドは画面の取り込みだけを行い、BGRA → RGB の変換と JPEG 保存はワーカースレッド（論理コア数 - 1、2〜5 本）が行う。開発ビルドでも速度を保つため、`Cargo.toml` の `[profile.dev]` で自分のクレートを opt-level 1、依存クレートを 3 にする（JPEG エンコーダはジェネリックで呼び出し側のクレートでコンパイルされる） | 計測（1920x1080・60fps 設定）: 開発ビルド **56fps**、本番ビルド **57fps**（v5 時点は 1.8fps）。`cargo test --lib capture_rate -- --ignored --nocapture` |
| T1 | 自動生成の project.json のトリム: 開始は `START_GUARD` と、録画冒頭 `AUTO_TRIM_START_SETTLE` 以内の大きな画面の変化（`BIG_CHANGE_CELLS` 以上。Snappi のウィンドウが消える等）が写ったフレームの遅い方（最初の操作より後にはしない）。終了は `END_GUARD` の手前。`AUTO_TRIM_MIN_DURATION` 未満の録画は切らない | `AUTO_TRIM_START_SETTLE` = **2.5s**, `AUTO_TRIM_MIN_DURATION` = **5.0s** |

## 8. 品質基準（メトリクス）

評価は **30fps**（`EVAL_FPS`）のカメラトラックで行う。対象が無い指標は「-」で合格扱い。v5 から M1・M7 の定義を変えた（止まっているマウスを主役にしない、寄らないと判断した操作を不合格にしない）。

| ID | 指標 | 基準 | 定義 |
|---|---|---|---|
| M1 | 寄っている間、**操作中**のカーソルがビューポート内にある割合 | **≥ 98%** | 寄っているフレームのうち、直近 `ACTIVE_CURSOR_MS` = 1.0s 以内にクリック・ドラッグ・スクロールがあったフレームで、カーソルがビューポート内にある割合 |
| M2 | クリック時刻にクリック位置がビューポート内にある割合 | **100%** | v5 と同じ |
| M3 | ズーム状態の切り替えの頻度 | **≤ 6 回/分** | v5 と同じ |
| M4 | 寄っている区間の最短長 | **≥ 2.0s** | v5 と同じ |
| M5 | カメラ速度の最大値 | **≤ 3.0 画面幅/秒** | v5 と同じ |
| M6 | ビューポートがフレーム外にはみ出すフレーム数 | **0** | v5 と同じ |
| M7 | 寄る区間の最初の操作でズームが完了している割合 | **≥ 90%** | 寄っている区間ごとに、寄り始め（直前の全体表示のフレーム）から `ZOOM_IN` 以上あとの最初の操作の時刻に、その後 1.0s の最大倍率の 95% まで寄り終えている割合 |

「寄るべき場面で寄り、主役を映しているか」はメトリクスでは決めず、シナリオごとの `expect.json`（§9.1）に**編集者ならこう映す**を書いて確かめる。

## 9. 評価データ

`testdata/recordings/<シナリオ>/` に録画データ（frames と audio を除く。`changes.jsonl`・タイトルを消した `window_events.jsonl` を含む）と `expect.json` を置く。取り込みは `python testdata/import_recording.py`（手順は `testdata/recordings/README.md`）。

| シナリオ | 内容 | 編集者ならこう映す（expect.json の要点） |
|---|---|---|
| `vscode-typing` | エディタで入力して保存 | 入力行と変換候補に寄る。保存ダイアログは全体を映す |
| `terminal` | クリックせずにターミナルで入力 | プロンプトの行に寄り、Enter の後は出力を映す。ターミナルの外は映さない |
| `browser-form` | フォームの入力欄を順に入力 | 入力欄と変換候補に寄る。ブラウザの外は映さない |
| `menu-navigation` | メニュー → 保存ダイアログ → 入力 | メニューからダイアログまで 1 つの場面として寄ったまま。ダイアログは全体を映す |
| `far-jumps` | 何も起きない場所を左上・右下と交互にクリック | 全体表示のまま |
| `drag-scroll` | タブのドラッグと長いスクロール | 止まったマウスには寄らず、スクロールしている内容を映す |
| `idle-gaps` | 操作 → 10 秒放置 → 操作 | 入力欄と変換候補に寄り、放置中は全体表示 |
| `window-mode`（合成） | ウィンドウ録画中にウィンドウを移動 | 移動後の入力行を映す |

### 9.1 expect.json

| kind | フィールド | 意味 |
|---|---|---|
| `zoomed_out` | `from_ms`, `to_ms`, `min_ratio`（既定 1.0） | 期間中、全体表示であるフレームの割合が `min_ratio` 以上 |
| `zoomed_in` | `from_ms`, `to_ms`, `min_ratio`（既定 1.0） | 期間中、寄っているフレームの割合が `min_ratio` 以上 |
| `visible` | `t_ms`, `x`, `y` | 時刻 `t_ms` に点 `(x, y)` がビューポート内 |
| `max_switches` | `max` | 録画全体での寄る/引くの切り替え回数が `max` 以下 |
| `framed` | `from_ms`, `to_ms`, `rect` = `[l, t, r, b]`, `min_ratio` | 期間中、主役の矩形がビューポートに収まっているフレームの割合が `min_ratio` 以上（誤差 4px） |
| `within` | `from_ms`, `to_ms`, `rect`, `min_ratio` | 期間中、ビューポートが矩形（操作中のウィンドウ）の中にあるフレームの割合が `min_ratio` 以上（誤差 4px） |

`framed` の矩形は、録画フレームと `changes.jsonl` から人が読み取った値（エンジンの出力から書き写さない）。

## 10. 評価ツール

```bash
cd src-tauri
cargo run --bin snappi-eval -- ../testdata/recordings/vscode-typing --metrics   # ショット・メトリクス・expect.json
cargo run --release --bin snappi-eval -- <recording_dir> --debug-video out.mp4   # frames がある録画のデバッグ動画
cargo run --release --bin snappi-eval -- <recording_dir>... --changes           # changes.jsonl を作り直す
cargo test --test camera_eval -- --nocapture                                    # 全シナリオの評価
cargo run -q --bin snappi-eval -- ../testdata/recordings --table                # §11 の表
```

デバッグ動画の描画: ビューポート（緑 = 寄っている / 灰 = 全体表示）、変化領域（桃の細枠）、いまのショットの主役（水色の枠）、カーソル（赤い点）、クリック（水色の輪）、スクロール（橙の輪）、キー入力（紫の四角）、タイムライン（寄っている区間・操作・R5 のガード・現在時刻）。

## 12. 既知の限界

- 変化領域は録画フレームの差分なので、録画のフレームレートが低いと粗くなる（旧録画の 1.8fps でも動くよう、反応の時間帯を 1.2s にしている）。
- 動画再生・アニメーションのように操作と無関係に大きく変化し続ける場所は、操作の直後に重なると主役に入ることがある（常に動いている場所の除外は小さな領域だけ）。
- 前面ウィンドウの矩形は開くアニメーションの途中の値が記録されることがあるため（v6 から矩形の変化も記録する）、主役を含まない矩形は使わない。
