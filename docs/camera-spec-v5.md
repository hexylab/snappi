## 1. 目的

v1〜v4 のカメラエンジンは毎回書き換えられてきたが、「何をもって良い動画とするか」の基準と、それを確かめる手段がなかったため改善が収束しなかった。

本仕様は、カメラ（ズーム・パン）のあるべき振る舞いを**ルールとパラメータで言語化**し、**自動で検証できるメトリクス**を定める。#29 の新エンジンは、`testdata/recordings/` のすべてのシナリオで本仕様のメトリクスと `expect.json` を満たすことをゴールにする。

パラメータの実体は `src-tauri/src/camera/spec.rs`、メトリクスの実装は `src-tauri/src/eval/metrics.rs` にある。値を変えるときは本書とコードの両方を更新すること。

## 2. 基本モデル

- カメラの状態は `(center_x, center_y, zoom)`（`camera::CameraState`）。座標はキャプチャ領域基準（フレーム左上が原点）の px。
- ビューポートは `center` を中心とする「フレームの `1/zoom` の大きさ」の矩形。
- zoom は **1.0（全体）** と **Z（固定倍率）** の2値のみを取り、遷移中だけ中間値を取る。
- 「どの区間で寄るか」（ZoomSegment 列, §4）と「寄っている間どこを映すか」（追従, §5）を分けて考える。
- エンジンの出力は `camera::CameraTrack { fps, frames: Vec<CameraState> }`。出力フレーム k（時刻 `round(k·1000/fps)` ms）ごとのカメラ状態で、エクスポートの出力フレームと 1 対 1 に対応する。

### 2.1 ズーム強さ Z

| 設定 | Z | 定数 |
|---|---|---|
| 控えめ | 1.5 | `ZOOM_SUBTLE` |
| 標準（既定） | 1.8 | `ZOOM_STANDARD` |
| 強め | 2.2 | `ZOOM_STRONG` |

ユーザー設定「ズーム強さ」で Z が決まる。区間ごとに Z を上書きできる（編集 UI, #30）。

## 3. 用語

| 用語 | 定義 |
|---|---|
| アクティビティ | クリック・キー入力・スクロール・ドラッグ（§4 R1）。`camera::extract_activities` |
| 注目点 | 寄っている間にビューポートに収めたい点（§5 F1） |
| 区間 (ZoomSegment) | 寄っている時間帯 `[start, end]`。start で寄り始め、end で引き始める |
| 寄っている（メトリクス上） | `zoom >= 1.25`（`ZOOMED_THRESHOLD`）。遷移の途中を含めて判定するためのしきい値 |

## 4. ズーム区間の自動生成ルール

| ID | ルール | パラメータ |
|---|---|---|
| R1 | クリック・文字入力・スクロール・ドラッグを「アクティビティ」とする。マウス移動だけでは寄らない。ドラッグはクリック（開始）と、リリース（ドロップ）の2つのアクティビティとして数える | ドラッグ判定: 押してから離すまでに `DRAG_MIN_DISTANCE` = **10px** 以上移動 |
| R2 | 間隔が `MERGE_GAP` 未満のアクティビティは1つの区間にまとめる | `MERGE_GAP` = **3.0s** |
| R3 | 区間は最初のアクティビティの `LEAD` 前に寄り始め、最後のアクティビティから `HOLD` 後に引き始める | `LEAD` = **0.6s**, `HOLD` = **1.5s** |
| R4 | 区間の長さは最低 `MIN_SEGMENT`（足りなければ end を延ばす）。区間同士の隙間が `MIN_GAP` 未満なら結合する（寄る→引く→寄るの往復を防ぐ） | `MIN_SEGMENT` = **2.0s**, `MIN_GAP` = **1.5s** |
| R5 | 録画冒頭と末尾の Snappi 自身の操作（開始・停止のホットキーやトレイのクリック）は対象外にする | 冒頭 `START_GUARD` = **1.0s**, 末尾 `END_GUARD` = **1.5s** 以内のアクティビティを無視 |

補足:
- R3 の寄り始めが録画開始（t=0）より前になる場合は t=0 から寄り始める。区間の end は録画の長さを超えない。
- 区間は「寄り始め〜引き始め」なので、遷移時間（§5.1）を含めた見た目上の寄っている時間は `[start + ZOOM_IN, end + ZOOM_OUT]` 付近になる。

## 5. 追従ルール

| ID | ルール | パラメータ |
|---|---|---|
| F1 | 寄っている間の注目点は、カーソル位置（`CursorSmoother` によるスムージング後）。文字入力中（直近のキー入力から `MERGE_GAP` 以内で、その後にクリックが無い間）は直近のクリック位置。区間内にクリックが無い場合（ターミナル等）はキー入力開始時のカーソル位置 | |
| F2 | 注目点がビューポートの中央 `DEAD_ZONE` の内側にある間はカメラを動かさない。外に出たときだけ、注目点がデッドゾーンの内側に戻るようにパンする | `DEAD_ZONE` = 幅・高さの **60%**。パンは臨界減衰バネ（半減期 `PAN_HALF_LIFE` = **0.2s**）、速度上限 `MAX_PAN_SPEED` = **2.5 画面幅/秒** |
| F3 | ビューポートは常にフレーム内に収める（画面外の黒が写らない）。注目点がフレーム端に近い場合は、注目点が中央に来なくてもよい | |
| F4 | ズームイン・アウト中は、注目点の画面上の位置がなるべく動かないように補間する（「点に向かって寄る」動き）。寄る直前の出力画面上の注目点の相対位置 `u = (p - vp.x) / vp.w` を保ったまま zoom を変え、F3 のクランプを最後に適用する | |
| F5 | 区間内で注目点がビューポート幅以上離れた場所へ移った場合は、パンで追う（F2 の速度上限内）。距離がビューポート幅の `FAR_JUMP` 倍以上で、次のアクティビティまで `REZOOM_MIN` 以上ある場合は、いったん全体表示に引いてから寄り直す | `FAR_JUMP` = **1.5 倍**, `REZOOM_MIN` = **2.5s** |

### 5.1 遷移

| 遷移 | 時間 | 補間 |
|---|---|---|
| ズームイン（1.0 → Z） | `ZOOM_IN` = **0.5s**（≤ `LEAD`。最初のアクティビティ時に寄り終えるため） | ease-in-out（cubic） |
| ズームアウト（Z → 1.0） | `ZOOM_OUT` = **0.7s** | ease-in-out（cubic） |

## 6. 品質基準（メトリクス）

すべて `eval::metrics::Metrics::compute(&RecordingData, &CameraTrack)` で計算し、評価は **30fps**（`EVAL_FPS`）のカメラトラックで行う。対象が無い指標（寄る区間が無い、クリックが無い等）は「-」と表示し合格扱いとする。

| ID | 指標 | 基準 | 定義 |
|---|---|---|---|
| M1 | 寄っている間にカーソルがビューポート内にある時間の割合 | **≥ 98%** | 寄っているフレームのうち、その時刻の生のカーソル位置（最新のマウス移動・クリック・スクロール位置）がビューポート内にある割合。カーソルがキャプチャ領域外のフレームは除く |
| M2 | クリック時刻にクリック位置がビューポート内にある割合 | **100%** | R5 のガード外のクリックについて、クリック時刻のフレームのビューポートにクリック位置が入っている割合。キャプチャ領域外のクリックは除く |
| M3 | ズーム状態の切り替え（寄る/引く）の頻度 | **≤ 6 回/分** | 隣り合うフレームで「寄っている」かどうかが変わった回数 ÷ 録画時間（分）。1分未満の録画は1分として数える |
| M4 | 区間の最短長 | **≥ 2.0s**（`MIN_SEGMENT`） | 「寄っている」フレームが連続する範囲の長さの最小値 |
| M5 | カメラ速度の最大値 | **≤ 3.0 画面幅/秒** | 隣り合うフレーム間のビューポート中心の移動距離 ÷ フレーム幅 ÷ 経過時間 の最大値。急なワープの検出 |
| M6 | ビューポートがフレーム外にはみ出すフレーム数 | **0** | ビューポートが `[0, W] x [0, H]` から 0.5px より大きくはみ出すフレーム数 |
| M7 | 最初のアクティビティ時刻にズームが完了している割合 | **≥ 90%** | R2 でまとめたアクティビティのまとまりごとに、最初のアクティビティ時刻の zoom が「まとまりの間の最大 zoom」の 95% まで遷移済み（`zoom >= peak - 0.05·(peak - 1)`）かつ peak が寄っている判定以上である割合 |

## 7. 評価データ

`testdata/recordings/<シナリオ>/` に録画データ（イベント・meta など小さいファイルのみ。frames はコミットしない）と `expect.json` を置く。

| シナリオ | 内容 |
|---|---|
| `vscode-typing` | エディタでクリックしてからコードを入力し、保存する |
| `terminal` | クリックせずにターミナルでコマンドを入力する |
| `browser-form` | ブラウザのフォームで複数の入力欄を順にクリックして入力する |
| `menu-navigation` | アプリのメニューとダイアログを操作する |
| `far-jumps` | 画面の左上と右下を交互にクリックする |
| `drag-scroll` | ドラッグ＆ドロップと長いスクロール |
| `idle-gaps` | 操作 → 10秒放置 → 操作 |
| `window-mode` | ウィンドウモードでの録画（録画中にウィンドウを移動） |

> **現状**: 現在のデータは `testdata/gen_synthetic.py` で生成した**合成データ**（`expect.json` に `"synthetic": true`）。Windows 実機で録画したデータに順次置き換える。録画する操作と取り込み手順は `testdata/recordings/README.md` を参照（`testdata/import_recording.py` が `frames/` と `audio.wav` を除いてコピーし、`expect.json` の下書きを作る）。

### 7.1 expect.json

シナリオ固有の期待値。`checks` の各要素は `kind` で種類を指定する（時刻は ms、座標はキャプチャ領域基準）。

| kind | フィールド | 意味 |
|---|---|---|
| `zoomed_out` | `from_ms`, `to_ms`, `min_ratio`（既定 1.0） | 期間中、全体表示であるフレームの割合が `min_ratio` 以上 |
| `zoomed_in` | `from_ms`, `to_ms`, `min_ratio`（既定 1.0） | 期間中、寄っているフレームの割合が `min_ratio` 以上 |
| `visible` | `t_ms`, `x`, `y` | 時刻 `t_ms` に点 `(x, y)` がビューポート内に写っている |
| `max_switches` | `max` | 録画全体での寄る/引くの切り替え回数が `max` 以下 |

```json
{
  "description": "操作 → 10秒放置 → 操作。放置中は全体表示に戻る",
  "checks": [
    { "kind": "zoomed_in", "from_ms": 2500, "to_ms": 6080, "min_ratio": 0.9 },
    { "kind": "zoomed_out", "from_ms": 9580, "to_ms": 14580 },
    { "kind": "max_switches", "max": 4 }
  ]
}
```

## 8. 評価ツール

```bash
cd src-tauri
# メトリクスと expect.json の判定を表示
cargo run --bin snappi-eval -- ../testdata/recordings/vscode-typing --metrics
# frames がある録画で、カメラの動きを描き込んだデバッグ動画を出力（ffmpeg が必要）
cargo run --release --bin snappi-eval -- <recording_dir> --debug-video out.mp4
# 全シナリオの評価（新エンジン完成までは ignore）
cargo test --test camera_eval -- --ignored --nocapture
# expect.json の下書きを出力（仕様 R1〜R5 から寄る/引く時間帯とクリック位置を求める）
cargo run --bin snappi-eval -- <recording_dir> --draft-expect
# 全シナリオのメトリクスを §9 の表の形式で出力
cargo run -q --bin snappi-eval -- ../testdata/recordings --table
```

デバッグ動画は**元フレーム全体**に次を描き込み、下端に区間タイムラインを付ける。

| 描画 | 意味 |
|---|---|
| 緑 / 灰の太枠 | ビューポート（寄っている / 全体表示） |
| 黄の細枠 | デッドゾーン（寄っている間のみ） |
| 赤い点 | カーソル（生の位置） |
| 水色の広がる輪 / 橙の輪 | クリック / スクロール |
| カーソル横の紫の四角 | キー入力 |
| タイムライン上段の緑 | 寄っている区間 |
| タイムライン下段の縦線 | アクティビティ（白=クリック / 紫=キー / 橙=スクロール / 水色=ドラッグ） |
| タイムラインの暗い赤 | R5 で無視する冒頭・末尾 |
| タイムラインの赤い縦線 | 現在時刻 |

## 9. ベースライン（旧エンジン v4）

旧エンジン（`export::encoder::legacy_camera_track`、既定設定）の合成データでの値。新エンジンはこれを下回らないこと。

| シナリオ | M1 | M2 | M3 | M4 (ms) | M5 | M6 | M7 | expect.json |
|---|---|---|---|---|---|---|---|---|
| `browser-form` | 100.00% | 100.00% | 2.0 | 17100 | 0.15 | 0 | 100.00% | **3/4** ✗ |
| `drag-scroll` | 100.00% | 100.00% | 2.0 | 16600 | 0.15 | 0 | 100.00% | 3/3 |
| `far-jumps` | **84.11%** ✗ | 100.00% | 2.0 | 15166 | 1.96 | 0 | 100.00% | 7/7 |
| `idle-gaps` | 98.38% | 100.00% | 4.0 | 5333 | 0.53 | 0 | 100.00% | 5/5 |
| `menu-navigation` | **95.91%** ✗ | 100.00% | 2.0 | 11466 | 1.03 | 0 | 100.00% | **2/3** ✗ |
| `terminal` | - | - | 0.0 | - | 0.00 | 0 | **0.00%** ✗ | **2/3** ✗ |
| `vscode-typing` | **97.95%** ✗ | 100.00% | 2.0 | 8200 | 0.39 | 0 | 100.00% | 4/4 |
| `window-mode` | 100.00% | 100.00% | 2.0 | 12933 | 0.70 | 0 | 100.00% | 3/3 |

（✗ は基準未達。frames を含まない状態での値。旧エンジンは frames があると画面差分も使うため、frames の有無で値が変わる）

旧エンジンの主な問題:
- **M1**: 遠いクリックの間（`far-jumps`）やメニュー操作（`menu-navigation`）、入力後のカーソル移動（`vscode-typing`）で、寄ったままカーソルがビューポートの外に出る。
- **M7 / terminal**: クリックの無いキー入力だけでは寄らない（R1 違反）。
- **expect（zoomed_out）**: 最後の操作から引くまでが長く、操作後も寄ったままの時間がある（`browser-form`, `menu-navigation`）。
- 合成データはカーソルの動きが単純なため、実録画では値が悪化する可能性が高い。実録画に置き換えたら再計測すること。
